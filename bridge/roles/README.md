# 她的人格（宪法）

这个目录是「小鲸鱼」的人格卡，**受 git 版本管理**。

## 为什么要 git

- 人格是她的“宪法”：改一条，行为就会变
- 所以每次改动都要**可追溯、可回滚**
- 改坏了能回到上一版；改好了能看到“她是怎么变成现在的样子的”

## 改人格的流程

```
1. 她提出建议（月度复盘 / 日常对话里说“我想改一下自己”）
2. 主人确认
3. 改 roles/小鲸鱼.md
4. 提交时写清楚「为什么改」，例如：
     git commit -m "人格：不再说『我明白了』——那是客服腔"
5. 提交后重启桥生效
```

## 提交规范

```
人格：<一句话说明为什么改>
```

不要写“更新人格卡”“修改文案”这种没有信息量的 message。

## 回滚

```bash
git log --oneline            # 看历史
git show <commit>:小鲸鱼.md  # 看某一版全文
git checkout <commit> -- 小鲸鱼.md   # 回到那一版
```

## 注意

- 人格卡是**提示词的一部分**，改完要重启桥才生效
- 卡越长，每次请求越贵；**加规则之前先想想能不能删一条旧的**
- `*.bak-*` 不进 git（历史版本由 commit 管）
